# Ovll Beta 엔진 정상 복귀: 확정/현행/미확정 구분 (2026-10-24)

**상태: 사용자 결정을 기다리는 논의 노트. 구현 명세나 승인된 제품 정책이 아니다.**
검토 근거: `docs/VISION.md`, `docs/superpowers/specs/2026-10-24-action-workshop-routing-design.md`, `docs/superpowers/specs/2026-10-24-native-workshop-function-calling-design.md`, 현재 beta 구현과 테스트.

## 사용자가 반복적으로 강조한 제품 방향
- Engine은 단일 사용자 요청을 한 번만 실행하는 함수가 아니라, **다수 요청의 큐·호출 ID·상태·전이를 관리**한다.
- 호출 경로는 `callId.workshop.skillDefine.defineDirect`처럼 명시적 행동을 포함한다. 각 요청의 맥락체·호출별 focus·room 맥락데이터 구분을 유지한다.
- Engine은 공급자·HTTP·캔버스 DOM·저장소 기술로부터 독립. Function Calling 제안과 실제 적용은 별도 사실로 검증.
- 이전 beta JSON Workshop을 되살리지 않고 Action Shell/행동별 계약으로 발전. `main` 미변경.
- 로컬 사용자 편집을 몰래 폐기하거나 가짜 완료 처리하지 않는다.

## 현행 구현 사실 (영구 합의가 아님)
- `skillDefine.defineDirect`, `canvasEdit.addBlock`만 서버 인메모리 자산으로 실제 적용. 다른 10개 행동, Hallway Return의 일반 재계획, 사용자 질문 대기/복귀는 미구현.
- 모델 중립 `inputSchema`는 Gemini 어댑터에서 REST `parametersJsonSchema`로 변환. 작업실 행동/ID와 모델 전송 스키마 분리.
- 요청/모델 동시 슬롯 3/2, 행동/호출 예산 24/40, 실행 활성화에 `OVLL_TEST_TOKEN` 길이 16 이상 요구는 **현재 시험용 값·임시 게이트**. 실서비스 정책 승인이나 사용자/테넌트별 인증이 아니다.
- 저장소와 컨텍스트 체크포인트가 서버 프로세스 메모리인 것은 **임시 토폴로지**. 동일 서버 재시작 이후 복구 불가. 프론트 로컬 편집은 별도 상태.
- 부분 성공 후 미지원 행동에서 중단된 요청도 서버 자산 재조회·미지원 행동 표시. UI 투영이 로컬 편집과 충돌하면 로컬 그래프를 보존하며, 캔버스에 보이지 않는다고 서버 적용이 취소된 것은 아니다.

## 보류된 설계 결정 (합의 전 제품 코드 변경 금지)
1. **캔버스 원본 소유권/동기화:** 브라우저 로컬 그래프와 서버 임시 그래프의 관계, 충돌 경고 뒤 사용자 승인·병합·재조회 정책. 엔진이 직접 로컬 그래프에 접근하는 방식은 기존 독립성 원칙과 충돌.
2. **인증/권한:** 공용 베타 테스트 토큰을 정식 권한 정책으로 고정하지 말 것. scope는 서버 검증 주체에서 받아야 하며, roomId 문자열 자체가 인증이 아님. 안전한 프로덕션 실행 조건은 별도 검토.
3. **Hallway Return/사용자 질문 대기:** 사용자가 이전에 제시한 정상 흐름의 중요한 미구현 부분. 어느 상태/오류를 Return에 전달하고 이전 applied operation을 재실행하지 않을지, waitingId와 사용자 답변을 어떤 요청에 귀속할지, 필요 예산·복구 기준을 **먼저 설계**. '원래 구현돼 있던 흐름'이라고 가장하지 말 것.
4. **다음 행동 확장:** 나머지 작업실 카탈로그 전체를 임의로 구현하지 않는다. 목표·스키마·사후조건·실제 UI 결과/검증 범위를 정하기 전 코드 양산 금지.

## 정상 복귀 작업의 범위
- 기존 코드의 독립성 누수(엔진의 Gemini 전용 schema 필드)를 모델 포트로 옮기고 테스트.
- 확인된 부분 적용을 미구현 전체로 오해시키던 UI 표시/자산 재조회 수정 및 테스트.
- AGENTS.md의 여러 시점 '현재' 문구를 단일 실제 현행 계약으로 통합.
- **새 작업실 행동, 서버/로컬 병합 정책, 인증 재설계, Hallway Return 구현은 이번 범위 밖**. 후속 작업은 독립 Superpowers 설계 승인 후 계획·TDD 순서로 수행.
