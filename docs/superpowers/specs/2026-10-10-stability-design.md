# Ovll 안정화 및 재사용 계약 개선

## 목적과 승인 범위

사용자가 종합 검토의 직접 개선을 요청했고, 변경 표를 확인한 뒤 함수 정의의 색상·SVG 선택 확장과 실행 중 마스코트 반응 소실 원인 분석을 추가했다. 기존 검토의 확인된 오류와 현재 경로에서 완성 가능한 안정화를 구현한다. 실제 AI 호출·유료 health probe는 하지 않는다. 대문·4개 행동계층·언어화, 동적 정의·노드 생성, 채팅 중심 UX는 유지한다.

## 설계

- 작업의 소유 대화와 UI 세대를 캡처하고 늦은 콜백을 소유권으로 검증한다. 채팅과 직접 실행의 진입·취소·정리를 일치시킨다.
- Task 문맥은 원래 목적·현재 변경 요청·보존 조건을 별도로 유지한다. 모델이 최신 발화에서 원래 조건을 다시 추측하게 하지 않는다.
- 실행 결과는 정의·설정·바인딩·유효 선행 결과의 의미 fingerprint와 연결한다. 이전 결과는 이력으로 남지만 현재 성공 표시에는 유효성 검사를 적용한다.
- 제어 흐름과 데이터 포트 규칙을 검증·계획·투영·역변환에 일치시킨다. UI 이동으로 논리 endpoint가 바뀌지 않는다.
- 모델 호스트는 목적과 필요한 정의만 조합하며, phase별 출력 계약과 지원 제공자의 응답 schema를 사용한다. 추가 routing 모델은 도입하지 않는다. 실제 사용량·수정·fallback을 반환한다.
- 함수는 선택 결과의 선행 범위와 입력 계약을 저장한다. 버전 수정은 같은 ID의 새 불변 버전으로 남긴다. 샘플 입력과 고정 값의 의미를 구분한다.
- 함수 색상은 기존 palette와 직접 HEX/color picker를 함께 제공한다. SVG는 서버 소유 icon key 체계를 유지하고 업무별 선택지를 늘리며 검색을 제공한다. 기존 SVG 모양은 바꾸지 않는다.
- 파일 읽기는 FileStore의 실제 원문을 읽는다. 지원하지 않는 파싱·잘림·원본 부재를 성공한 전체 분석으로 처리하지 않는다. PDF 전체 분석 능력을 구현 없이 선언하지 않는다.
- 산출물 잘림·행/열 누락은 사용자에게 명시한다. 생성 동시성·메모리·시간을 제한하고 임시 URL의 수명과 보존 여부를 구분한다.
- 예산은 admission 때 예약한다. 큐 대기부터 취소·deadline을 적용하며 실제 model calls와 논리 HTTP 요청을 구분한다.
- 큰 결과 보존, 저장 실패, 다중 탭 충돌을 명시적으로 처리한다. 공용 SQL 전환은 전제조건이 아니다.
- 노드 진행은 마스코트의 기존 workAtNode·성공·오류·취소 반응으로 전달한다. 과거 결과를 복원할 때는 반응하지 않는다. 진행 이벤트마다 같은 작업 애니메이션을 다시 시작하지 않는다.

## 경계

active-run graph adoption은 실행 fencing까지 필요한 별도 기능이다. 이번에는 지원하지 않는 경계를 명확히 하고, 안전한 실행 종료 경계에서 필요한 후속 조정을 가능하게 한다. 후속 모델 호출은 실제 미완료·입력 대기 경우에만 제한된 전체 예산으로 허용한다. 모든 노드 뒤 자동 심사를 추가하지 않는다.

마스코트 반응 소실의 확인된 원인은 새 로컬 경로의 반응 전달 누락이다. 화면을 보지 않고 미세한 시선 떨림의 모든 원인이 해결됐다고 주장하지 않는다. 기존 reduced motion·숨김 탭 보호를 보존한다.

## 완료 기준

대화 전환·그래프 수정·여러 턴·동적 연결·새 자료 재사용·원문 부재·산출물 한도·동시 admission·취소·저장 충돌을 실제 런타임/fake provider로 검증한다. 함수 색상과 신규 icon key가 저장·재개 후 유지된다. 실제 실행 노드에서만 마스코트가 일하고 종료 후 상태를 정리한다. 문서는 현재 구현·제한·과거 검증을 구분한다. main에 관련 변경을 한 번의 검증된 커밋으로 묶고 APP_VERSION을 올린다.
