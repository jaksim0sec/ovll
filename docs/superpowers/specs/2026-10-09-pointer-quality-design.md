# OvllPointer quality recovery

Approved scope: the independent review and visualization, followed by the user's instruction to implement and make one final commit. VISION.md remains authoritative. Entry, communication/IR/execution/functionization, and response remain logical responsibilities, not mandatory model calls.

## Product contract
Node definitions remember useful repeatable and user-custom work: purpose, instructions, semantic IO and stable constraints. Reuse compatible definitions, create new definitions when useful, and keep this request's instruction/input on the instance. Basic, custom and generated definitions share graph, execution and presentation contracts. Preserve legacy conversations, canvas gestures and local storage; no database, authentication or paid-service requirement.

## Changes
1. Publish a derived Pointer catalog from the existing server node catalog. Seed local snapshots and model context with canonical built-ins; retain custom definitions. Add optional bounded presentation metadata. Use the existing icon library and colors, real data port types, and explicit control ports.
2. Carry task purpose, instance requests and inputs into node execution. Normalize inline/ref outputs once before storing or forwarding. Preflight supported execution capabilities. Adapt existing local file input and artifact creation and explicitly declared exclusive branch routing, without arbitrary tool execution.
3. Use one browser coordinator for confirmed action results, dependency checks, narrow context reads, bounded blocked-run reassessment and direct saved-function replay. Failure must not masquerade as applied. Keep atomic graph patches; adopt changes only between runs and preserve compatible model results within one request.
4. Preserve complete target outputs. Format actual final results and artifact links; avoid internal port traces and silent truncation. Existing complete deliverables do not require another model call.
5. Compress all 25 instruction modules with a behavior coverage audit. Explain actual user-facing abilities and limits; omit irrelevant protocol/vendor details, not useful capability information. Ground graph selection in inspectability, reuse and outcome value rather than keywords or ability to answer directly. Keep dynamic definition examples alongside existing-definition reuse.
6. Correct documentation activation claims, bump APP_VERSION once, and make one atomic main commit after verification.
