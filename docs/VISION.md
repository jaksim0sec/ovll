# Ovll — Vision & Direction

> **문서 성격:** 공개 가능한 제품 가치와 장기 방향성. 구현 완료 현황, 세부 아키텍처, MVP 명세와 성능 검증 결과는 별도로 관리한다.

## 1. 오블은 무엇인가?

**Ovll(오블)은 AI와 함께 수행한 작업을 쉽게 함수화해 재사용하고, 그 과정과 결과를 사용자와 AI가 함께 이해·소통·조정할 수 있도록 만드는 AI 작업 환경이다.**

오블은 LLM을 대체하는 별도의 지능이 아니다. 모델의 언어 이해·추론·생성·도구 활용 능력을 사용자의 목적과 작업 방식에 연결하고, 작업에서 얻은 절차와 결과를 다음 업무에 활용할 수 있도록 돕는다.

오블이 추구하는 궁극적인 성과는 **사용자의 총노동 감소와 모델 활용성의 극대화**다. 핵심 실용 가치는 **대화에서 유용한 작업을 자연스럽게 함수로 발전시키는 것**이며, 핵심 경험은 **그 작업을 사용자가 이해하고 개입할 수 있는 방식으로 시각화·소통하는 것**이다.

## 2. 누구의 어떤 문제를 해결하는가?

오블이 우선 주목하는 사용자는 **AI 채팅으로 자료를 분석·정리·작성하거나 비슷한 절차를 반복하면서, 매번 지시를 다시 만들고 중간 결과를 옮기고 검토하는 사람**이다. 이는 초기 문제를 구체화하기 위한 대상이며, 장기적인 사용자 범위를 제한하는 선언은 아니다.

이들은 이미 능력 있는 LLM을 사용하고 있지만 다음과 같은 노동을 반복한다.

- 전에 잘된 지시와 절차를 다시 설명하고 재구성한다.
- 작업과 도구 사이에서 자료·중간 결과·수정 사항을 직접 전달한다.
- AI가 무엇을 근거로 어떤 행동을 실제 수행했는지 파악하고 검증하기 어렵다.
- 새로운 자료나 목적에 맞춰 기존 작업을 조정하려면 다시 처음부터 지시해야 한다.
- 자동화 도구를 도입하면 오히려 사용자가 구조와 설정을 조립·관리해야 할 수 있다.

워크플로우를 구성하거나 프롬프트를 저장하는 기능 자체는 이미 존재한다. **오블이 차별화하려는 것은 구조화의 존재가 아니라, 자연스러운 대화와 작업 속에서 유용한 절차를 함수로 승격하고, 그것을 사용자와 AI가 함께 이해·수정·재사용하는 경험**이다.

이는 제품이 입증해야 할 차별화 방향이지, 현재 모든 경쟁 제품보다 우수하다고 검증된 사실은 아니다.

## 3. 가치의 우선순위

### 3.1 핵심 실용 가치 — 간편한 함수화와 반복 재사용

오블의 중심 기능적 가치는 반복적인 LLM 작업의 **함수화**다.

함수화는 단순한 프롬프트 저장을 넘어, 작업의 목적·입력과 출력의 의미·필요한 절차·판단 기준·후속 처리 등을 재사용 가능한 형태로 남기는 것을 지향한다.

사용자는 복잡한 프로그래밍이나 노드 조립을 선행하지 않고도 AI와 작업할 수 있어야 한다. 성공한 작업이 있다면 필요한 부분을 함수로 발전시키고, 다음에는 새로운 자료나 조건을 제공하여 재사용할 수 있어야 한다. 함수는 이후 수정·확장하거나 다른 작업과 결합할 수도 있어야 한다.

**함수의 수나 그래프의 복잡성이 아니라, 두 번째 작업부터 실제로 줄어든 사용자 노동이 가치의 기준이다.**

### 3.2 핵심 경험 — 소통 가능한 시각화와 양방향 협업

오블의 시각화는 단순한 실행 과정 전시가 아니다. **AI가 구성하고 수행하는 작업을 사용자가 이해하고, 질문하고, 바꾸고, 다시 AI에게 전달할 수 있는 소통 방식**이다.

사용자는 필요할 때 작업의 관계, 입력, 결과, 진행 상태와 근거를 살펴보고 일부를 수정할 수 있어야 한다. AI 역시 사용자에게 질문하거나 새로운 작업을 제안하고, 사용자의 개입을 다음 행동에 반영할 수 있어야 한다.

다만 모든 사용자가 모든 노드를 항상 보거나 조립할 필요는 없다. 구조는 필요할 때 드러나고, 평소에는 자연스러운 대화와 결과 중심의 경험이 유지되어야 한다.

### 3.3 개인화된 총노동 감소

같은 목표에도 사용자마다 원하는 설명의 밀도, 검토 방식, 작업 순서, 자동화와 개입의 경계는 다르다.

오블은 사용자의 요청·맥락·선호와 현재 작업 상태를 반영해 소통 방식과 작업 구성을 조정하는 방향을 지향한다. 이를 통해 입력 준비, 지시 반복, 실행, 확인, 수정, 재사용까지 포함한 **전체 노동량**을 줄여야 한다.

사용자가 시스템 사용법에 더 많은 시간을 쓰게 만드는 자동화는 좋은 자동화가 아니다.

### 3.4 모델의 능력과 자율성 보존

오블은 일반 대화부터 복잡한 작업까지, 상황에 적합한 방식을 선택할 수 있어야 한다. 간단한 질문에서는 모델의 자연스러운 소통 능력을 활용하고, 구조화·실행·재사용이 유리할 때 그 가능성을 확장한다.

AI는 고정된 역할을 선언받는 데 그치지 않고, **자신이 실제로 할 수 있는 일, 오블이 제공하는 수단, 현재 상태와 제약, 행동의 실제 결과**를 파악한 상태에서 판단해야 한다. 오블이 가진 방식만 무조건 강제하거나, 존재하지 않는 능력을 사용할 수 있다고 알려서는 안 된다.

### 3.5 모델의 발전과 함께 유지되는 가치

오블의 작업 자산은 특정 모델이나 공급자의 한계에만 의존하지 않아야 한다. 모델이 발전하면 향상된 능력을 활용하고, 모델이 바뀌어도 가능한 범위에서 작업의 목적·재사용 가능한 구조·결과와 기록의 가치를 유지해야 한다.

이는 모델 간 품질이 동일하다는 약속이 아니라, **모델의 발전이 오블의 가치 감소가 아니라 사용자 경험의 발전으로 이어지도록 하려는 방향**이다.

## 4. 함수화와 자율성이 충돌할 때

**함수는 재사용할 목적과 사용자가 지정한 계약·제약을 보존하지만, 그 목적을 달성하는 방법까지 필요 이상으로 고정하지 않는다.**

모델은 그 경계 안에서 자료에 맞는 접근법을 선택하고, 필요한 작업을 새로 정의하거나 기존 작업을 조정할 수 있어야 한다. 사용자가 특정 순서나 절차를 고정하도록 지정했다면 그 의도를 우선한다.

따라서 오블의 함수화는 무조건 고정된 자동화도, 매번 달라지는 무제한 자율 실행도 아니다. **보존해야 하는 것과 모델이 판단할 수 있는 것을 구분하는 재사용**을 지향한다.

이 원칙을 실제 IR·실행·함수 계약으로 구현하는 방법은 기술 문서에서 정한다.

## 5. 오블이 지향하는 상호작용

사용자가 목표와 자료를 자연어로 제시하면, AI는 실제 능력과 현재 작업 상태를 바탕으로 대화·질문·작업 구성·실행 중 적절한 행동을 선택할 수 있어야 한다.

작업이 복잡해지면 AI는 목적에 맞는 작업 단위를 동적으로 정의·수정하고 연결할 수 있어야 한다. 결과나 제약이 달라지면 추가 작업을 제안하거나 재구성할 수 있다. 사용자는 필요한 순간에 구조와 결과를 살피고 개입할 수 있다.

그리고 유용한 작업은 **대화 속 일회성 처리에서 다음에 다시 쓸 수 있는 함수로 발전**할 수 있어야 한다. 재사용할 때는 가능하면 이전 구조를 다시 조립하기보다 새로운 입력과 변경 조건에 집중한다.

오블은 모델이 *제안한 행동*과 시스템이 *실제로 수행한 행동*을 구분해야 한다. 실행되지 않은 일을 완료했다고 표시하거나 확인되지 않은 사실을 확정해선 안 된다. 작업을 둘러싼 불투명성을 줄인다는 것은 모델 내부 추론을 모두 공개한다는 뜻이 아니라, **사용자가 확인할 수 있는 목적·입력·선택된 행동·실행 상태·결과를 명확히 연결하는 것**이다.

## 6. 제품 설계 원칙

1. **실제 효용이 우선이다.** 결과 품질과 반복 노동의 절감이 노드 수·기능 수·시각적 완성도보다 중요하다.
2. **목적이 구조보다 우선한다.** 모든 요청을 워크플로우로 만들지 않으며, 대화로 충분할 때는 대화가 최선이다.
3. **함수화는 자연스러워야 한다.** 재사용을 위해 사용자가 개발자처럼 작업 구조를 처음부터 조립하지 않도록 한다.
4. **작업은 이해하고 개입할 수 있어야 한다.** 시각화는 사용자와 AI 사이의 양방향 소통을 위한 도구다.
5. **자율성은 실제 상태와 계약 위에서 작동한다.** 모델의 판단을 존중하되 없는 능력이나 실행 사실을 만들어내지 않는다.
6. **기술은 사용자와 모델을 제한하기보다 돕는다.** 특정 도구·모델·고정된 절차가 목적이 되지 않도록 한다.

## 7. 초기 집중과 장기적인 방향

**초기에는 반복적인 LLM 업무 한 가지에서 대화 → 작업 수행 → 함수화 → 새로운 입력으로 재사용까지의 경험을 충분히 유용하게 만드는 데 집중한다.** 구체적인 첫 유스케이스, 정량 목표, 구현 범위는 제품·기술 실행 문서에서 검증하고 결정한다.

**장기적으로는** 대화, 분석, 생성, 자료 처리 등 다양한 업무에 대응하는 범용 AI 작업 환경을 지향한다. 사용자별 작업 맥락과 재사용 가능한 자산이 축적되고, 사용자가 AI의 실제 행동을 이해하고 수정할 수 있는 양방향 협업 도구로 발전시키는 것이 방향이다.

범용성은 처음부터 모든 기능을 만드는 명분이 아니다. **범용적인 확장 가능성과 좁은 초기 검증은 함께 추구할 수 있다.**

## 8. 가치를 판단하는 기준

제품의 성공은 기능이 구현되었다는 사실만으로 판단하지 않는다. 동일한 목적과 조건에서 직접 모델을 사용하는 경험과 비교해 다음을 평가해야 한다.

- **노동:** 작업을 처음 완료하고 같은 유형을 반복할 때 사용자가 들인 지시·조작·수정·검토 노력
- **품질:** 모델의 본래 역량과 사용자 제약을 얼마나 충실하게 보존했는지
- **재사용:** 유용한 절차가 실제로 함수로 남고, 새 입력으로 다시 활용되었는지
- **소통과 통제:** 사용자가 AI의 작업 상태를 이해하고 필요한 부분을 수정할 수 있었는지
- **적응성:** 사용자와 자료, 선택한 모델이 달라져도 작업 가치가 지속되는지

구체적인 수치와 기준 업무는 별도 실행 문서에서 정한다. 위 항목은 이미 달성했다는 주장이 아니라 앞으로의 제품 판단 기준이다.

**오블이 만들어야 할 것은 AI를 더 복잡하게 쓰는 방식이 아니라, AI와 함께한 작업이 이해 가능하고 재사용 가능한 가치로 남는 경험이다.**
