# Ovll — Vision & Direction

> **문서 성격:** 공개 가능한 제품 가치와 장기 방향성. 구현 현황이나 기술 설계의 확정본이 아니다.

## 1. 오블은 무엇인가?

**Ovll(오블)은 AI의 능력을 사용자의 목적과 작업 방식에 맞춰 연결하고, 그 과정을 이해·조정·재사용할 수 있도록 하는 범용 AI 작업 플랫폼이다.**

오블은 기존 대규모 언어 모델(LLM)을 대체하거나 별도의 지능을 구현하려는 제품이 아니다. 대신 모델이 가진 언어 이해, 추론, 생성 및 도구 활용 능력을 실제 작업에 효과적으로 연결하고, 사용자가 그 과정에 자연스럽게 참여할 수 있는 환경을 만드는 것을 목표로 한다.

오블이 추구하는 것은 단순한 작업 자동화를 넘어선다. AI의 작업을 사용자가 이해하고 조정할 수 있는 형태로 경험하게 하며, 반복적인 작업은 손쉽게 재사용할 수 있도록 발전시키는 것이다.

궁극적으로 **사용자마다 다른 목적과 작업 방식에 적응하여 총노동을 줄이고, 모델이 가진 능력을 최대한 활용하는 것**이 오블의 핵심 가치다.

## 2. 문제 인식

오늘날의 AI 모델은 점점 더 복잡한 작업을 스스로 수행할 수 있게 발전하고 있다. 그러나 모델의 능력이 향상되는 것과 사용자가 그 능력을 실제 업무에서 효율적으로 활용하는 것은 서로 다른 문제다.

일반적인 AI 사용 환경에서는 다음과 같은 어려움이 발생할 수 있다.

- **반복적인 지시와 작업:** 유사한 작업을 수행할 때 이전 절차와 지시를 다시 구성해야 한다.
- **사용자의 수동적인 중개:** 여러 작업이나 도구 사이에서 결과를 직접 전달하고 후속 작업을 지시해야 한다.
- **제한적인 작업 가시성:** AI가 실제로 어떤 정보를 활용했고, 어떤 행동을 수행했으며, 무엇이 완료되었는지 확인하기 어렵다.
- **작업 맥락의 손실:** 중간 결과, 선택한 근거, 수정한 결정, 성공한 작업 절차가 다음 작업으로 자연스럽게 이어지지 않을 수 있다.
- **사용자에게 맞지 않는 자동화:** 정해진 구조와 사용법에 사용자가 적응해야 하며, 자동화를 구성하는 과정 자체가 새로운 노동이 될 수 있다.

기존의 워크플로우 및 자동화 도구들은 작업을 구조화하고 재사용하는 능력을 이미 제공한다. 따라서 **작업을 구조화한다는 사실 자체만으로는 충분한 차별적 가치가 되지 않는다.**

오블이 해결하고자 하는 문제는 작업 구조의 부재만이 아니다. 그 구조를 사용자의 목적과 맥락에 맞게 구성하고, 사용자가 쉽게 이해하고 소통하며 실제로 활용할 수 있도록 만드는 것이다.

## 3. 핵심 가치

### 3.1 사용자 중심의 업무 효율성

오블의 가장 상위 목표는 사용자의 **총노동을 줄이는 것**이다.

효율성은 AI의 응답 속도나 자동화 단계 수만으로 평가하지 않는다. 사용자가 목적을 설명하고, 자료를 준비하고, 작업을 실행하고, 결과를 검토·수정하고, 이후 같은 작업을 다시 수행하기까지의 전체 과정을 고려한다.

기능이 많아지거나 내부 구조가 정교해져도 사용자가 더 많은 조작과 관리에 시간을 사용한다면 오블이 추구하는 효율성과 충돌한다.

**사용자가 시스템을 운용하는 데 쓰는 노력보다, 시스템이 사용자에게 줄여주는 노력이 커야 한다.**

### 3.2 이해하고 소통할 수 있는 AI 작업

오블은 작업 과정을 단순히 보여주는 것에 그치지 않고, AI와 사용자 사이의 실질적인 소통 수단으로 만들고자 한다.

AI가 수행하는 작업은 사용자에게 이해 가능한 방식으로 표현될 수 있어야 한다. 사용자는 필요한 경우 작업의 구성과 연결 관계, 활용된 정보, 실제 실행 상태 및 결과를 확인하고 조정할 수 있어야 한다.

반대로 모든 사용자가 항상 복잡한 내부 구조를 확인하거나 직접 수정해야 하는 것은 아니다.

**시각화는 장식이나 독립적인 목표가 아니라 AI의 작업을 이해하고, 질문하고, 조정하고, 협업할 수 있도록 만드는 경험의 일부다.**

### 3.3 자연스러운 함수화와 재사용

오블의 핵심 능력 중 하나는 반복적인 AI 작업을 손쉽게 함수화하는 것이다.

여기서 함수화는 단순한 프롬프트 저장보다 넓은 개념이다. 작업의 목적, 수행 절차, 입력과 출력의 관계, 판단 기준과 후속 처리까지 재사용 가능한 형태로 구성하는 것을 지향한다.

이 과정은 사용자가 복잡한 프로그래밍이나 워크플로우 설계를 직접 수행하지 않더라도 가능해야 한다.

AI와 함께 수행한 작업에서 유용한 절차를 재사용 가능한 기능으로 발전시키고, 다음 작업에서는 필요한 입력이나 조건만 변경하여 활용할 수 있어야 한다. 함수는 한 번 정의된 뒤 영원히 고정되는 대상도 아니다. 필요에 따라 수정하고 확장하며 다른 작업과 결합할 수 있어야 한다.

**함수화의 목적은 구조를 저장하는 것 자체가 아니라, 반복되는 지능 노동을 줄이는 것이다.**

### 3.4 모델의 자율성과 역량 극대화

오블은 모델이 가진 능력을 불필요하게 제한하지 않아야 한다.

AI는 사용자 목적과 현재 상황을 이해하고, 필요한 작업을 판단하며, 적절한 행동을 선택할 수 있어야 한다. 그 과정에서 새로운 작업 구조를 만들거나 기존 구조를 수정하고, 필요한 정보를 요청하거나, 작업 결과를 검토해 다음 행동을 결정할 수 있어야 한다.

그러나 모든 요청을 반드시 구조화된 워크플로우로 처리해야 하는 것은 아니다. 일반적인 질문과 대화에서는 모델 본연의 소통 능력을 충분히 활용해야 하고, 구조화와 실행이 유용한 작업에서 그 능력을 자연스럽게 확장해야 한다.

오블의 존재로 인해 모델이 원래 수행할 수 있는 작업의 품질이나 선택권이 불필요하게 줄어들어서는 안 된다.

**오블은 모델의 능력을 특정한 작업 방식에 가두는 것이 아니라, 그 능력을 더 효과적으로 발휘할 수 있는 환경을 제공한다.**

### 3.5 사용자 맞춤형 작업 방식

같은 목표를 가진 사용자라도 선호하는 설명 방식, 작업 절차, 검토 기준, 허용 가능한 자동화 범위는 다를 수 있다.

오블은 모든 사용자에게 동일한 업무 구조를 강요하는 대신, 사용자의 요청과 맥락, 선호, 기존 작업 상태를 반영하는 방향을 지향한다.

어떤 사용자는 간단한 답변만 필요할 수 있고, 어떤 사용자는 중간 결과와 근거를 직접 확인하고 싶어 할 수 있다. 또 어떤 작업은 자동으로 완료하는 것이 적절하지만, 중요한 결정 전에 사용자와 소통해야 하는 경우도 있다.

**오블은 상황과 사용자에 맞는 소통 및 작업 경험을 제공하는 것을 목표로 한다.**

### 3.6 모델과 기술로부터 독립적인 지속 가치

AI 모델의 능력과 기술은 계속 변화한다. 오블은 특정 모델이나 공급자의 특성에 지나치게 의존하는 제품이 되어서는 안 된다.

모델이 발전하면 그 발전된 능력을 활용할 수 있어야 하며, 모델이 변경되더라도 사용자에게 축적된 작업 구조와 결과, 재사용 가능한 자산의 가치가 최대한 유지되어야 한다.

이것이 모든 모델의 품질이 동일하다는 의미는 아니다. 모델의 실제 능력과 사용 가능한 수단의 차이를 인정하면서도, 오블의 고유한 가치가 특정 모델의 일시적인 한계에만 의존하지 않도록 하는 것이다.

**모델이 발전할수록 오블이 제공할 수 있는 작업 경험 역시 함께 발전해야 한다.**

## 4. 오블이 지향하는 상호작용

오블은 사용자와 AI가 일방적으로 명령하고 응답하는 관계를 넘어, 작업의 목적과 상태를 공유하며 협업하는 관계를 지향한다.

사용자는 원하는 결과를 자연스럽게 요청할 수 있다. AI는 현재 사용할 수 있는 능력과 작업 상태를 바탕으로 적절한 행동을 선택하고, 필요한 경우 작업을 구성하거나 실행할 수 있다.

작업을 수행하면서 새로운 정보나 문제가 발견되면 추가 행동을 선택하거나 사용자에게 질문할 수 있다. 사용자 역시 AI가 구성한 작업을 확인하고, 일부를 수정하고, 다른 방향을 제시하거나, 유용한 작업을 재사용 가능한 기능으로 보관할 수 있다.

이 과정에서 AI가 제안한 행동과 실제로 이루어진 행동은 구분되어야 한다. 실제로 실행되지 않은 작업을 완료했다고 표시하거나, 확인되지 않은 정보를 검증된 사실처럼 전달해서는 안 된다.

장기적으로 오블은 이러한 상호작용을 통해 AI 작업의 불투명성을 줄이고, **사용자와 AI가 서로의 상태와 의도를 더 명확하게 이해하며 협업할 수 있는 범용 작업 환경**으로 발전하는 것을 목표로 한다.

## 5. 제품 설계 원칙

1. **목적이 구조보다 우선한다.** 작업 구조, 노드, 함수, 시각화는 사용자 목적을 달성하기 위한 수단이다.
2. **필요한 만큼만 개입한다.** 간단한 대화나 직접 실행으로 충분한 작업에 불필요한 구조를 강요하지 않는다.
3. **복잡성은 시스템이 부담한다.** 내부적으로 정교한 구조를 사용하더라도 사용자가 모든 개념을 이해하고 관리하도록 요구하지 않는다.
4. **AI의 자율성을 존중한다.** 모델이 목적과 상황에 맞는 행동을 선택할 수 있도록 하되, 실제 실행 가능성과 결과는 신뢰할 수 있어야 한다.
5. **사용자는 개입할 수 있어야 한다.** 자동화된 작업도 필요한 경우 이해하고 검토하고 수정할 수 있어야 한다.
6. **작업의 가치는 축적되어야 한다.** 유용한 결과와 작업 절차를 다음 작업에서 다시 활용할 수 있어야 한다.
7. **모델의 능력을 훼손하지 않는다.** 시스템의 편의나 고정된 구조가 모델 본연의 업무 수행 능력을 불필요하게 제한해서는 안 된다.
8. **실제 효용을 기준으로 발전한다.** 기술적 복잡성이나 시각적 완성도보다 결과 품질과 사용자 노동 감소를 우선한다.

## 6. 오블이 지향하지 않는 것

- 모든 작업을 노드나 워크플로우로 변환하는 것
- 사용자가 직접 복잡한 자동화 구조를 조립하게 만드는 것
- 작업 과정을 시각적으로 표현하는 것만으로 가치를 증명하는 것
- 특정 모델의 역할이나 행동을 하나의 고정된 방식으로 제한하는 것
- 모든 판단을 AI에 맡기거나, 반대로 모든 행동을 시스템의 고정 규칙으로 결정하는 것
- 단순히 더 많은 기능이나 더 긴 자동화 절차를 제공하는 것

오블의 성공은 얼마나 복잡한 작업 구조를 생성했는지가 아니라, **사용자가 얼마나 효과적으로 목표를 달성하고 그 경험을 다시 활용할 수 있는지**에 달려 있다.

## 7. 장기 방향성

**첫째, 범용적인 AI 작업 환경.** 대화, 분석, 생성, 자료 처리, 반복 작업 등 서로 다른 유형의 업무를 하나의 경직된 사용법에 가두지 않고 다룰 수 있는 환경을 지향한다.

**둘째, 양방향으로 소통 가능한 AI.** AI의 행동과 실제 작업 상태를 사용자가 이해할 수 있게 만들고, 사용자의 개입과 조정이 다시 AI의 다음 행동에 반영되는 경험을 발전시킨다.

**셋째, 사용하면서 발전하는 개인화된 작업 자산.** 사용자와 AI가 함께 수행한 작업에서 유용한 결과와 절차를 축적하고, 이를 다음 업무에서 더 간편하고 효과적으로 활용할 수 있도록 한다.

이 세 방향은 서로 독립적인 목표가 아니다. 작업의 이해 가능성은 사용자의 개입을 돕고, 개입과 조정은 작업의 완성도를 높이며, 성공적인 작업의 함수화와 재사용은 반복적인 노동을 줄이는 데 기여할 수 있다.

## 8. 성공의 기준

오블의 가치는 기능의 존재만으로 입증되지 않는다. 제품은 실제 사용 과정에서 다음 질문에 답할 수 있어야 한다.

- 사용자가 기존 AI 환경보다 적은 노력으로 원하는 작업을 완료할 수 있는가?
- 모델이 가진 능력을 불필요하게 손상시키지 않고 활용할 수 있는가?
- AI가 수행한 작업을 사용자가 이해하고 필요한 부분에 개입할 수 있는가?
- 반복되는 작업을 저장하고 다시 사용하는 과정이 충분히 간편한가?
- 사용자마다 다른 목적과 작업 방식에 유연하게 적응할 수 있는가?
- 모델과 기술이 발전하더라도 축적된 작업의 가치가 유지되는가?
