# 워크플로우 실행 및 파일 반환 무결성

## 조사 범위와 증거

사용자 제보: 기존 조사 결과의 PDF 요청 후 연구/생성 노드가 연결되지 않은 채 완료 안내가 나왔고, 연구 노드는 재실행 상태였다. 파일 카드 대신 `/api/artifacts/...` Markdown 문자열이 출력됐으며 수동 연결 시 `AMBIGUOUS_INPUT_PRODUCERS`가 발생했다.

실제 사용자 브라우저의 그래프·실행 기록·산출물 저장 기록은 제공되지 않았다. 따라서 해당 사건의 정확한 IR, 모델 응답, 서버 실행 여부를 확정하지 않는다. 아래 원인은 현재 코드와 회귀 재현으로 확인한 결함이다. 활성 실행 경로는 브라우저 Local runtime과 stateless model host다. 비활성 서버 저장소를 사건의 실행 주체로 가정하지 않는다.

## 확인된 원인과 변경

| 계층 | 확인한 문제 | 변경과 결과 |
| --- | --- | --- |
| 캔버스 → 그래프 | 모델이 지정한 `inputBindings`는 연결선 없이 존재할 수 있다. 새 데이터 연결을 추가할 때 대상 포트의 기존 literal binding이 남아 커널이 두 입력 공급자를 감지했다. | 새 데이터 연결의 대상 포트 binding만 동일 패치에서 제거한다. 다른 포트와 flow 연결은 보존하며 실제 다중 공급자는 계속 거부한다. |
| 결과 현재성 | 일시적인 후속 요청/채팅 이력까지 fingerprint에 포함해 원본 조사 결과를 오래된 것으로 표시할 수 있었다. 부모 실행 증거가 누락된 결과도 현재 결과로 인정할 수 있었다. | 지속적인 objective/constraints 및 실제 노드 의미로 현재성을 판단한다. 모든 부모의 결과·fingerprint·상태 증거를 검증한다. 안전하게 검증되는 기존 fingerprint만 호환한다. |
| 실행 입력/출력 | 포트 선언과 래퍼만으로 실제 값 검증이 충분하지 않았고, 빈 결과나 빈 문서가 성공으로 이어질 여지가 있었다. | 실제 representation, 필수 출력, JSON 값과 export 내용을 검사한다. flow 연결은 데이터 입력을 대신할 수 없다. |
| 원본 재사용 | 새 PDF 실행이 과거의 유효한 조사 결과를 실행 입력으로 재사용할 경로가 부족했다. | 현재 그래프·입력·부모 증거·파일 입력을 만족하는 이전 model task 결과를 재사용한다. 명시적으로 실행한 대상은 다시 실행하며 파일 생성 등 도구는 실행한다. |
| 모델 조정 | 이전 결과의 읽기 참조와 현재성이 모델 문맥에 노출되지 않았다. 행동 없는 완료 문구가 그대로 사용자 응답이 될 수 있었다. | 크기가 제한된 `availableResults` 인덱스로 읽기 참조를 제공한다. 대표적인 근거 없는 완료 표현은 실제 행동 결과나 입력 필요 안내로 대체한다. |
| 산출물 반환 | LocalActions가 파일 객체를 Markdown 링크로 바꾸고 app의 세 진입점이 텍스트만 전달했다. 기존 카드 렌더러는 `options.artifacts`를 받지 못했다. | `{text, artifacts}`를 일반 채팅·저장 함수 실행·캔버스 실행에서 전달한다. 확인된 도구 실행의 최신 파일만 기존 카드/미리보기로 반환한다. |
| 지침 | 기존 조사 결과를 재사용하는 데이터 연결과 직접 입력의 배타성, 실행 사실과 응답 책임이 충분히 구체적이지 않았다. | 실제 결과 참조 → 기존 source → createFile 데이터 연결을 안내한다. 직접 입력 교체와 확인된 산출물 메타데이터 반환을 명시한다. |

`AMBIGUOUS_INPUT_PRODUCERS` 검증 자체는 오류가 아니다. 충돌한 입력 상태를 만드는 캔버스 패치를 수정했다. 연결이 없는 노드도 실제 독립 입력이 있으면 정당하게 실행할 수 있으므로, 단순히 모든 독립 export를 금지하거나 추정 연결을 자동 생성하지 않는다.

## 검증

- 유료/실제 모델 호출 없이 회귀 검사와 실제 런타임·그래프·파일 생성 코드를 사용했다.
- 잘못된 출력, 빈 export, 누락된 부모 증거, flow-only 입력, 연결 binding 충돌, 오래된 파일 카드와 행동 없는 완료 안내를 검증했다.
- 일반 채팅·저장 함수·캔버스 실행에서 실제 app 함수가 파일 메타데이터를 전달하는지 검사했다.
- 기존 조사 → 새 데이터 연결 → 원본 재사용 → 실제 PDF 바이트 생성 → 파일 저장 → 채팅 카드 전달을 통합 검증했다. PDF는 `%PDF-` 헤더와 원본 내용 보존을 확인했다. 원본 수정 후 source/descendant의 현재성이 해제되고 이전 카드가 억제되는지도 확인했다.
- 전체 `npm test`: 572개 통과. 독립 검토의 관련 검사 41개 통과, Critical/Important 지적 없음.

## 남은 한계

행동 없는 자연어 완료 표현의 방어는 표현 감지와 실제 실행 근거를 결합한 것이며 모든 자연어의 의미를 보증하지 않는다. 모델이 올바른 원본과 연결을 선택하는 실제 호출 품질은 이번 무과금 검사 범위 밖이다. 사건 당시 브라우저 실행 기록이 없으므로 해당 PDF의 실제 생성 여부나 원본 일치 여부는 별도 확인이 필요하다. 브라우저 화면에서의 실제 렌더링과 배포된 서비스의 동작은 이번 로컬 코드 검사로 확인했다고 주장하지 않는다.
