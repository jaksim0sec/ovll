상위 기준은 [제품 비전](../VISION.md)이다. 기술은 비전을 실현하기 위한 수단이며 사용자 노동 감소, 모델 역량 보존, 양방향 소통과 동적 함수화를 판단 기준으로 삼는다.

## 현재 코드의 진입점

- `server.js`: Express 서버 엔트리, HTTP API, 현재 플래너/노드 카탈로그
- `backend/ai/`: 현재 Gemini 기반 대화·실행 코드
- `backend/artifacts/`: 결과물 문서화·저장·PDF 렌더링
- `backend/http/`: 요청 중단 등 HTTP 보조 기능
- `front/`: 웹/PWA UI, 캔버스, 브라우저 실행기, 사용자 함수 저장
- `mobile/`: Capacitor 앱 포장
- `test/`: 현재 코드의 회귀 테스트
- `instructions/`: 현재 지침의 위치와 이후 계층형 지침 라이브러리 이관 기준

이는 현재 파일의 **소유 위치**를 설명한다. `backend/`로 이동했다고 기존 브라우저 실행기나 플래너가 이미 서버로 재구축된 것은 아니다.

## 이후 설계에서 구체화할 경계

1. 서버 관제탑이 제공하는 실제 능력과 에이전트의 판단·선택
2. 대문 행동 선택과 소통·IR·실행 등 행동 계층의 점진적 지침 공급
3. 사용자 지침·현재 요청·상태·작업 맥락의 독립된 적용 축
4. 동적 IR 정의·연결·함수화·실행 결과의 검증 가능한 계약
5. 실행 권위와 상태 저장, 모델·도구 어댑터, 실제 사용자 노동 측정

설계와 코드의 차이, 제안/승인/구현 여부를 명시한다. 한 번에 모든 계층을 고치기보다 상위 책임을 확정한 뒤 수직 단위로 개편한다.
