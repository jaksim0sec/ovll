# Ovll 첫 반복 재사용 수용 기준 — 문서 방향성 기반

## 제품 판단의 출처와 한계
- 상위 기준: `docs/VISION.md` §3.1·§3.4·§4·§7·§8. 오블은 대화→유용한 작업→함수화→새 입력 재사용에서 사용자 **총노동을 줄여야** 한다. 모델을 대체하거나 구조를 강제하지 않는다.
- 기술 현황: `docs/architecture/STABILITY_2026-10-10.md`, `docs/architecture/EXECUTION_DELIVERY_INTEGRITY_2026-10-10.md`. 활성 실행은 브라우저 Local, 별도 모델 호스트. 출력·파일의 사실성/현재성은 실제 실행 증거로 확인한다.
- 2026-10-08 방향성 조사(질적 사례 92개)에서 제시된 좁은 업무 가설: 복수 자료를 처리하고 근거를 비교·출력한 뒤 같은 절차를 다음 자료에 적용하는 작업. 이는 수요의 정량 검증이 아니다.

## 첫 검증 업무
**자료 2건의 주장·근거 추출 → 결과 비교 → 검토 가능한 보고서**, 성공한 절차를 하나의 함수로 저장 후 다른 자료 쌍에 재적용한다. 캔버스는 자료·결과·근거 연결을 확인하는 선택적 공간이며, 매번 노드를 다시 그리도록 강제하지 않는다.

## 수용 기준
1. **대화/첫 실행:** 두 자료와 목적/제약을 제시하고 AI가 적절한 직접 답변·재사용·동적 구조를 고르게 한다. 사용자가 작업 전에 그래프를 반드시 설계하지 않는다.
2. **함수화:** 실제로 유용했던 실행의 선행 노드, 서로 다른 노드의 지속 지시, IO/근거 연결, 고정 제약을 저장한다. 검증하지 않은 모델 출력은 함수가 저장됐어도 `draft`다.
3. **재사용:** 자료 A1/A2, B1/B2, C1/C2에 동일 구조를 적용할 때 저장된 그래프 수정 **0회**, 바뀐 외부 입력 **2개/실행**, 노드별 request 유지, 자료 혼입 **0건**, 실제 데이터 링크의 각 출처 보존.
4. **실패 처리:** 잘못된 object/array 입력은 모델/파일 도구 호출 *전에* `FUNCTION_INPUT_TYPE_MISMATCH`로 거절. 잘못된 키·권한·그래프 개정·실행 대상은 조용히 추측하거나 수행하지 않는다.
5. **산출물:** 비교 결과/원본 근거에 접근할 수 있어야 하며 파일 생성 요청 시 확인된 artifact 객체만 파일 카드로 전달한다. PDF 바이트와 실제 브라우저 렌더는 별도 종단 간 검증한다.
6. **제품 효용 평가:** 동일 모델의 직접 사용 대비 첫 작업 및 두 번째·세 번째 작업의 **지시 재작성 횟수, 입력/클릭 수, 수동 자료 복사, 검토·수정 소요 시간, 오류 복구, 모델 호출·토큰, 결과 충실도**를 기록한다. 결과 품질이 떨어지면 시간 절감만으로 성공 판정하지 않는다.

## 2026-10-11 현재의 결정적 오프라인 증거
- `test/ovllPointerFirstReuseAcceptance.test.js`: 저장→localStorage 재읽기→새 입력 바인딩→두 자료별 독립 추출→실제 데이터 링크로 비교→3회 재실행을 기존 함수/플래너/런타임으로 검증. 회차마다 2개 입력·3개 노드 수행·결과 차이/출처 보존, 원래 샘플 불변을 확인.
- `test/ovllPointerLocalFunctions.test.js`: object/array 입력 타입 위반을 함수 실행 전에 거절하고 정상 값은 수용한다. 기존에는 이 위반이 조용히 통과했다.
- 오프라인 테스트는 **고정된 executor 출력**만 검증한다. 실제 Gemini 능력, 결과 문장 품질, UX 시간 절감, 브라우저 파일 카드 표시, 모바일 조작 편의는 검증하지 않는다.

## P2/P3 정책과 평가 게이트
- P2의 core/entry/IR/run/function/modelContract/validation 책임은 유지한다. 동적 정의·복합 행동·기존 정의 재사용은 결정 트리의 배타적 종류가 아니라 상황에 따라 조합 가능한 능력이다.
- 선택적 모듈 공급의 **설계안(미활성)**: 항상 제품 목적·사용자 의도·실행 권한·정의와 그래프 변경의 의미·전체 행동 가능성·정확한 출력 형식을 제공한다. 세부 모듈만 단계별로 평가해 선택하고, 필요 능력이 사라지거나 모호해지면 기존 전체 공급으로 복귀한다.
- 키워드나 모델 이름으로 실행·동적 노드 생성 기능을 봉쇄하지 않는다. 옵션은 공급자 별로 비활성 기본값을 유지한다. 전체 모델 호출 횟수/폴백 비용과 품질을 **같은 모델·설정·시나리오**로 반복 비교한 후에만 P3 조건부 공급·typed wire 활성화를 검토한다.
- 실제 모델 호출 자원·브라우저가 없는 환경에서는 실모델 A/B 및 실제 카드 검증이 *미실행* 상태이며 체크리스트에서 완료로 바꾸지 않는다.

## 다음 제품 판단
사용자의 첫 성공과 두 번째 사용에서 감소한 총노동 및 결과 품질이 직접 모델 대비 실제로 개선됐는지 측정한다. 개선되지 않았다면 노드/마스코트/프롬프트 설정을 추가하기보다, 입력 선택→저장→재사용→결과 확인에 필요한 조작을 줄이는 방향을 우선한다.
