# 모델 지침 라이브러리 — 개편 준비 영역

**현재 상태: 설계·이관 전.** 아래는 지침의 목표 구조이며, 실행 시 계층을 동적으로 로딩하는 기능이 구현되었다는 의미가 아니다.

## 원칙

- **대문 지침:** 에이전트에게 정체성 문구만 주입하지 않고, 실제 작업 상태·가능한 행동·모델 역량·시스템이 제공하는 수단을 알려준다.
- **행동 계층:** 소통, 동적 IR 정의/수정, 실행 등 선택한 행동에 들어갈 때 필요한 세부 지침을 점진적으로 제공한다. 행동의 존재를 숨기거나 진입 후 다른 행동을 봉쇄하지 않는다.
- **독립된 맥락 축:** 사용자 설정, 현재 요청, 작업 상태, 자료 및 제약은 한 줄로 직렬 결합된 단계가 아니라 선택된 행동에 필요한 범위로 공급한다.
- **사실과 지시 구분:** 실제 실행 결과·사용 가능한 도구·지원 모델 능력은 서버의 검증 가능한 정보여야 한다. 지침으로 없는 능력을 만들어내지 않는다.
- **모델 역량 보존:** 특정 렌더러나 워크플로우 사용을 무조건 강제하지 않는다. 실제 선택 가능한 방법과 한계를 명시한다.
- **비용·품질 검증:** 무조건 많은 지침을 전달하지 않으며 프롬프트 캐시, 호출 수, 재시도, 결과 충실성을 함께 측정한다.

## 현재 지침의 실제 위치

- `server.js`: planner/IR 생성 규칙과 스키마·행동 선택 일부
- `backend/ai/geminiExecution.js`: 대화·실행·마무리 프롬프트 및 현재 모델 호출 방식
- `front/js/app.js`: 채팅/워크플로우 경로 결정과 실행 연계

**아직** 위 코드의 지침이 이 디렉터리로 추출되지 않았고, 공통 대문/행동별 모듈/사용자 설정의 계층적 해석도 구현되지 않았다.

다음 단계에서 상위 행동 계약과 실제 상태 공급 방식부터 확정한 뒤, 역할별 모듈과 활성 조건을 작성한다. 먼저 빈 디렉터리나 가상의 지침을 대량으로 생성하지 않는다.
