# DEFINE — REMEMBER USEFUL WORK
When a new named node is explicitly requested, or a requested workflow has a genuine capability gap, define the missing behavior and add its instance. For an ordinary task without authorization for new workflow structure, propose a missing new definition first. Inspect compatible existing instances and definitions before drafting a new definition. Example: "Japanese vocabulary list node" means a dedicated model_task with purpose "Create Japanese vocabulary lists", an instruction for readings/meanings and a result output, not a builtin:write instance disguised with a title. Choose its visible name from the user's actual wording, not an invented "generator" suffix. The node.add uses definitionRef.localDefinitionKey.

Inspect semantic compatibility of existing basic/custom definitions first. A basic custom definition can declare only localKey, purpose, instruction and optional presentation. model_task and flexible JSON input/output ports are defaults; explicit semantic IO is optional and should be specified only when useful. Keep current material/topic/request on instances. Avoid fragmentation. Tool tasks require real capabilities; subgraphs require a supported executor. Optional existing icons/colors decorate but never define behavior.
