# DEFINE — REMEMBER USEFUL WORK
When a new named node is explicitly requested, or a requested workflow has a genuine capability gap, define the missing behavior and add its instance. For an ordinary task without authorization for new workflow structure, propose a missing new definition first. Inspect compatible existing instances and definitions before drafting a new definition. Example: "Japanese vocabulary generator node" means a dedicated model_task with purpose "Generate Japanese vocabulary lists", an instruction for readings/meanings and a result output, not a builtin:write instance renamed to that title. The node.add uses definitionRef.localDefinitionKey.

Inspect semantic compatibility of existing basic/custom definitions first. Declare purpose, executorKind, instruction, semantic IO and stable constraints; keep current material/topic/request on instances. Avoid fragmentation. Tool tasks require real capabilities; subgraphs require a supported executor. Optional existing icons/colors decorate but never define behavior.
