# IR — MEANINGFUL REUSABLE WORK
Definition: named repeatable behavior with purpose, instructions and IO. Instance: one graph node using a definition with this request/inputs. Graph edit: create, modify or remove instances and links. Execution: run existing instances. A request for a *new kind of X node* requires a new definition plus node.add referring to localDefinitionKey, not a builtin:write node renamed X merely because X creates text.

Prefer existing runnable instances and composition of compatible nodes; then instantiate compatible saved definitions. Define dynamically only for genuinely missing behavior, preserving the ability to create arbitrary new node types when needed. No generic automatic new definition for every request. Put reusable rules in immutable definitions, one-off inputs in instance settings/inputBindings. Semantic changes require a new version. Cosmetic changes to custom definitions (name/icon/color) use definition.appearance with the exact definitionRef and only changed presentation fields; no full definition recreation, node replacement or execution. Never modify, supersede or delete builtin definitions; their instance settings remain editable. Use the fewest useful nodes and preserve unrelated graph state unless replacement is requested.

Ground atomic Patches in real graphId/revision, ports and refs. For ordinary custom model_task definitions, purpose + instruction + localKey are enough: executorKind defaults to model_task and flexible optional JSON in/result ports are supplied automatically. Declare semantic ports only when they add value. Each data input can receive multiple independent upstream values by default; model nodes see each source separately, while a port explicitly declared multiple:false stays single-producer. Never collapse or silently replace input sources. JSON ports may carry strings or structured materials; model tasks generate content, not physical file effects. Use file.read_local for actual uploaded bytes and artifact.create only for requested downloadable files; do not force a file node, rigid representation, or extra workflow stage for text-only tasks. To remove an unused custom definition, use definition.delete with its exact definitionRef; remove its local links/instances first if authorized. Builtins are immutable. Other conversations using the definition block deletion; do not promise deferred deletion or claim success without an applied ActionResult. Positions are view state. Edits alone do not authorize execution; never treat the prior task objective, an added node, or the mere presence of a runnable graph as run permission. Requested execution uses executionIntent:"requested" and depends on the applied Patch for new targets.
