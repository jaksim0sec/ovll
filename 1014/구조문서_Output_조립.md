# Output — 호출 조립서

> 설계 기록 · Output Base 지침 원문과 서버 조립 책임을 분리한다. 현재 구현 완료를 의미하지 않는다.

## 역할

Output은 단순한 메시지 출력기가 아니라, **현재 사용자 요청의 종결 시점에 결과·기록을 종합하고 다음 대화의 연속성을 위한 맥락을 확정하는 계층**이다.

- 보고서의 summary처럼 여러 작업에서 생성된 정보, 기록, 확인된 결과를 **사용자 요청 전체의 의도**를 기준으로 종합한다.
- 최종 답변의 언어적 구성과 전달을 맡고, 후속 대화가 자연스럽게 이어질 여지를 둔다. 불필요한 질문이나 후속 제안을 강제하지 않는다.
- **최종 `contextBlock`**은 이번 요청의 **완료·종결 시점 기준 상태**를 기록한다. 실제 완료된 일과 미해결 사항을 구별하며, 이후 완료 요청의 맥락 조회에 활용될 수 있다.
- **`contextData`**는 세션 전체에 남길 흐름·주제·결정·지속 조건을 갱신한다. 최종 맥락체와 같은 요약을 중복 보관하지 않는다.
- 종결은 새로운 실행이나 계획을 개시하지 않는다. 실제 수행되지 않은 일을 완료로 표현하지 않는다.

## 모델 입력

- 현재 요청의 `contextBlock` (기존 `intent`, `progress`; 서버에서 현재 호출에 맞춰 제공하는 `focus`)
- 기존 `contextData`
- 이번 요청 동안 확인된 실행 결과, 생성 정보와 기록, 관련 참조

원본 기록·실행 상태·산출물은 별도로 관리한다. 모델에는 최종 응답과 갱신에 필요한 자료를 제공한다.

## 지침 조립 순서

1. `베이스지침_Output.md` — 종합·최종 언어화·맥락 확정의 전체 역할
2. `공통지침_JSON_규칙.md` — 활성 블록들의 출력을 하나의 JSON 객체로 구성
3. `조립지침_언어_생성.md` — `languageBlock` 작성
4. `조립지침_맥락체_갱신.md` — `contextBlock`의 모델 작성 필드 갱신
5. `조립지침_맥락데이터_생성.md` — `contextData` 갱신

## 출력

```json
{
  "languageBlock": "...",
  "contextBlock": {
    "intent": "...",
    "progress": "..."
  },
  "contextData": {
    "overallFlow": "...",
    "currentTopic": "...",
    "details": "..."
  }
}
```

위는 **키 구성 예시**이며 구체적인 내용 작성 규칙은 각 조립지침이 담당한다. `focus`는 서버 작성 필드이므로 모델 반환 `contextBlock`에 포함하지 않는다.

## 경계 및 별도 결정 사항

- **최초 복도의 즉시 응답**은 `languageBlock` + 종결 시점의 얕은 `contextBlock` + 갱신된 `contextData`를 같은 호출에서 반환한다. 이 경로는 별도의 Output 재호출로 동일한 응답·맥락을 다시 생성하지 않는다.
- **작업 계획의 `terminate`** 및 회귀 복도에서 `terminate`를 반환하는 경우에는 Output 계층에서 최종 결과 종합과 맥락 갱신을 수행한다.
- 출력 계층은 확인된 자료를 종합한다. 성공 여부를 임의로 추정하거나 새 작업을 실행하지 않는다.
- 서버가 실제 호출에 어떤 결과와 기록을 얼마만큼 전달할지에 관한 세부 계약은 아직 미확정이다.
