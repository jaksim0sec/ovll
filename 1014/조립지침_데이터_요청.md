# InformationRequestBlock — v1.0

Write `need` as `[[datasetName, ...parameters], ...]`.

**Datasets**
- `["originalReq", n]` — Exact user requests, from current (0) through n requests back.
- `["chatContext", n]` — Final context objects of the last n completed requests.
- `["skillDef", [names]]` — Skill definitions by exact names.
- `["canvasSkill", [ids]]` — Canvas Skill Block (Skill Node) instance data by exact IDs; missing IDs return `false`.
- `["skillList"]` — Compact skill index: name, purpose, iconKey, input/output signatures.

**Rules**
- Request only additional data necessary for the current task.
- Prefer exact names/IDs; otherwise, use `skillList` to identify candidates.
- Keep `n` small. Use `[]` when no additional data is needed.
- Never invent identifiers.

## 개발 시 참고사항 (모델 지침에 포함하지 않음)

- 구분선 위 **InformationRequestBlock**만 모델에 전달한다. 이 절은 서버 구현·향후 확장 참고용이다.
- `need`는 최종 반환 JSON의 한 키이며, 전체 JSON 구조·블록 조립·조회 실행 및 결과 전달은 서버가 담당한다.
- 각 요청은 `[datasetName, ...parameters]` 형태다. 정보의 전달 대상은 요청이 포함된 상위 실행 맥락으로 결정하므로 `need` 내부에 목적지를 중복 지정하지 않는다.
- `originalReq`: `n=0`은 현재 요청만, `n=1`은 현재 요청과 직전 요청을 뜻한다. 서버가 요청 순서를 관리한다.
- `chatContext`: 최근 완료된 요청 `n`개의 **최종 종결 언어화 시점에 생성·보존한 맥락체**를 제공한다. 현재 진행 중인 요청의 맥락체나 서버의 일반 맥락데이터와 혼동하지 않는다.
- `canvasSkill`: 요청한 ID별로 해당 캔버스 스킬 블록(스킬 노드) 정보 또는 `false`를 연결해 가볍게 반환한다. `skillDef`는 요청한 정확한 이름별로 존재하는 정의를 반환한다.
- `skillList`: 정의된 스킬의 이름·목적(`purpose`)·SVG 키(`iconKey`)·축약 입출력 시그니처로 구성한 경량 색인이다. 식별자가 불명확할 때 후보를 찾는 용도이며, 캔버스 인스턴스 목록과는 다르다.
- 추후 추가할 데이터셋 후보: **장기 메모리 조회**, **PDF 제작 지침서 조회** 등. 실제 필요성과 반환 규격을 별도로 설계한 후 추가하며, 현 v1.0 모델 지침에는 포함하지 않는다.
